# 中文写作与去味规范

润色中文稿的最后一遍按本文件执行。原则：最小有效编辑，保留作者的观点锋利度，只削 AI 味。

## 排版

- 全角标点；中英文之间留一个空格（盘古之白）；数字与英文单位间留空格，与中文单位不留。
- 破折号"——"预算：长文全篇不超过 2 处，且必须明显优于逗号、句号或冒号才保留。禁止当节奏拐杖。
- 加粗仅用于术语首次定义（如 **spec 可执行率**），禁止用于情绪强调。全篇加粗不超过 10 处。
- 冒号用于列举、定义、引语，不用于"戏剧性揭晓"。

## 作者声音：工程师风格

1. 第一人称直陈判断和经历，不演内心戏。「这两条讨论让我停了很久」→「这两条讨论对我有所启示」；「我读完愣住了」→「我读完发现一个矛盾」。
2. 叙述声音不用网络化口语：转疯了 / 不服 / 拉满 / 破防 / 天花板（形容词义）→ 流传很广 / 体感相反 / 具体程度描述。直接引语原样保留。
3. 形容词让位给名词、动词、数字。「巨大的提升」→「review 从 6 小时压到 20 分钟」。
4. 比喻只在承担论证时使用（如博尔赫斯的地图论证"精确 spec 收敛为代码"），装饰性比喻删除（"最大的裂缝"→"最大的分歧"）。
5. 动作描述具体化：「翻来覆去看了几遍」→「反复读了」；「挖了一遍底」→「逐一核实了」。

## 反模式（附修正示例）

1. **二元对照句**："不是 X，是 Y / 不是 X，而是 Y"。仅保留承担实际论证的（争论双方的真实立场对立），装饰性的改直陈。
   例：「不是不可能，是经济上残忍」→「做得到，但经济上残忍」。
   全篇此类句式不超过 4 处。
2. **自问自答**："为什么会这样？因为……"。删掉问句，直接陈述。
   例：「漂移为什么必然？因为改代码更便宜」→「漂移必然发生，因为改代码更便宜」。
3. **清嗓子开场**：值得注意的是 / 不得不说 / 众所周知 / 说实话 / 坦白讲 / 这里必须说一句 / 让我们。删掉，直接说事。
4. **自夸修饰语**：对自己的论证用"漂亮的 / 巧妙的 / 精彩的 / 更狠的"。删掉，论证好不好读者判断。
5. **排比三连成瘾**：恰好三个形容词、三个例子、三条理由且无内容必然性时，砍到最强一项或按内容需要的数量。
6. **金句收尾**：把观点压成格言、比喻、mic-drop 句子收尾。删掉，用文中已有的最具体一句或一个可执行动作收尾。
7. **总结复述结尾**：综上所述 / 总而言之 / 回顾全文。整段删。
8. **互联网黑话**：赋能 / 抓手 / 闭环 / 打通 / 沉淀 / 助力 / 践行 / 势能 / 组合拳。换成具体动词和具体结果。
9. **翻译腔**：「进行了分析」→「分析了」；「作为一个开发者来说」→「作为开发者」；「基于……的情况下」→「在……时」。
10. **弱化词堆叠**：一定程度上 / 某种意义上 / 或许可以说 / 在某些场景下。要么直接下判断，要么写明成立的前提条件。
11. **万能空洞词**：深度 / 全面 / 系统性 / 立体化，无具体所指时删除。

## 保留项（不是 slop，不要误删）

- 承担论证功能的比喻（如用博尔赫斯的地图论证"精确 spec 收敛为代码"）。
- 作者的强观点和判断句。规范的目标是削掉包装，不是磨平立场。
- 直接引语中的任何句式（引语原样保留）。
