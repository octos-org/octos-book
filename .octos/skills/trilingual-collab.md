# 三语内容协作规范

协作分四步：研究 → 成文 → 审查 → 去味润色。每一步的规则如下。语言相关的润色规则按目标语言读取对应参考文件，动笔或润色前必读。

## 零、语言路由

确定目标语言（看用户要求和发布渠道），先读对应参考文件再动笔：

- 中文 → `references/zh.md`
- English → `references/en.md`
- 日本語 → `references/ja.md`

一篇文章多语言版本并行时，三个文件都读。深度技术文章的研究方法论，如已安装 technical-writing skill，与本 skill 配合使用（它管研究深度，本 skill 管协作流程与语言质量）。

## 一、事实纪律（所有语言共通）

1. **URL 铁律**：从不凭记忆写 URL。每个链接必须来自本次会话的搜索/抓取结果，或用户提供。凭印象拼出来的链接是最常见的编造形态。无法当场核实的链接标注"链接待核"，不装作确定。
2. **每个事实主张至少搜索验证一次**。无法核实的明确标注"存疑/未能核实"，绝不含糊带过，也绝不为了行文顺畅悄悄删掉存疑标记。
3. **高风险声明抽查清单**（发布前逐项过）：
   - 具体数字，特别注意区分**增幅与占比**（"X 增加了 31%"和"31% 的 X"是两个断言）
   - 收购、融资、发布日期这类一次性事件（标注来源）
   - 人名拼写。转录稿是 ASR 错误重灾区（如 Geoff Huntley 被转成 Jeff Hundley），修正时注明原误拼
   - 职位与现状（"现任 X"必须搜索确认，不吃训练记忆）
4. **三类内容分开标注**：他人观点（注明出处）、已验证事实（带链接）、作者自己的延伸分析（明确声明，如"本节为作者延伸分析"）。
5. 引语必须可溯源。二手转述与原文有出入时，以原文为准并注明。

## 二、协作流程

1. **研究**：先验证再写。整合新素材（访谈、评论区、续篇文章）时，先与现有稿逐条对照，分成三类处理——确认（不动）、新增（合入）、矛盾（按事实错误优先处理）。
2. **成文**：见第三节规则。
3. **审查**：勘误优先级固定为 **事实错误 > 技术公平性 > 结构问题 > 措辞**。对被比较的技术做公平描述，不省略对方的能力。修正后重新输出完整文章，不要只给 diff。
4. **去味润色**：按目标语言的参考文件做最后一遍。这是独立的一遍，不与内容修改混在同一次编辑里。

## 三、成文规则（共通）

- 标题是论点，不是话题。"从 X 看 Y 的边界"优于"聊聊 X"。
- 结论前置：文章、章节、段落、句子，都先给结论再给细节。
- 数字优先于形容词。"review 从 6 小时压到 20 分钟"优于"大幅缩短 review 时间"。
- 不预防性道歉（"本文不是为了鼓吹 X"），不鸡汤收尾。结尾落在具体事实、引语或可执行动作上。
- 自己的框架与术语自然引用、不硬植入；引用一次点到为止。
- **作者声音：工程师风格**（三语通用）。第一人称用于直陈判断、立场和经历，不用于表演反应；不做戏剧化的情绪节拍；叙述声音不使用网络化口语（直接引语除外）；形容词让位给名词、动词和数字。各语言的具体规则见对应参考文件。
- 不在不同章节重复同一论点，需要时合并到一处。

## 四、共通反模式（语言无关）

- 伪深刻金句收尾：删掉，用文中已有的最具体一句收尾，或补一个朴素的行动建议。
- 总结复述式结尾：读者刚读完，不需要复述。
- 重要性吹捧（"标志着关键时刻""具有里程碑意义"）：陈述事实，让读者自己判断。
- 模糊归因（"专家认为""研究表明""业内普遍认为"）：点名来源，或删掉该断言。
- 机械脚手架：满屏"（注：存疑）"、句中情绪性加粗、装饰性列表、超过内容需要的层级结构。存疑标注要有，但集中收纳，不淹没正文。

## 五、跨语言规则

- **母语重写，不做翻译**：各语言版本共享事实、数字、链接，不共享句式。一种语言里的修辞直译到另一种语言就是新的 slop。
- **术语表**：通用技术术语（Rust、RLVR、harness、spec、agent、token、review 等）在三语中保持英文原文；项目自有术语同样保持原文（如 CBV = Contract / Boundary / Verification）。仅当目标语言存在业界通行译名时才使用译名。
- **一致性即事实纪律**：各语言版本的事实、数字、链接必须一致。版本间断言不一致，按一级事实错误处理。
- 标点与排版遵循各语言自身规范，细则见各参考文件。
